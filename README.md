## Syllabus checklist

Tick each topic off once you can explain it without notes. The "Must know" facts are the ones questions turn on. Each lesson link goes to the complete, free lesson.

### Domain 1: Understand Git and GitHub basics

**Weight: 28%.** Version control and Git fundamentals, how GitHub relates to Git, accounts, organizations and enterprises, the GitHub Flow, Markdown, and GitHub Desktop and Mobile. Official weight range 25–30%.

📝 Revision notes: [Domain 1: Understand Git and GitHub basics](notes/domain-1-understand-git-and-github-basics.md)

- [ ] **Version control fundamentals**
  <br>Describe the purpose and benefits of version control; Explain the difference between Git and GitHub; Identify key Git concepts such as repositories, commits, and branches.
  - 📖 Lesson: [Git vs GitHub: Version Control Fundamentals for GitHub Foundations (GH-900)](https://www.savemycert.com/revision/github-foundations/git-vs-github-version-control-fundamentals/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)
  - Must know: Version control records each change with author, time and message, lets you restore or compare any committed version, and lets people work in parallel on branches.
  - Must know: Only committed content is recoverable: uncommitted edits, a file's life before it was added, and ignored files are not in the history.
- [ ] **Working with GitHub**
  <br>Describe GitHub accounts, organizations, and enterprise options; Explain the GitHub Flow for collaboration; Identify uses of Markdown for clear communication in issues and pull requests; Recognize when to use GitHub Desktop and GitHub Mobile.
  - 📖 Lesson: [Working with GitHub: Accounts, Plans, the GitHub Flow, Markdown, Desktop and Mobile (GitHub Foundations GH-900)](https://www.savemycert.com/revision/github-foundations/github-accounts-flow-markdown-desktop-mobile/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)
  - Must know: Personal accounts are people; organizations are shared owners that nobody signs in to; enterprise accounts (Enterprise Cloud and Server) manage policy and billing for many organizations.
  - Must know: GitHub recommends one personal account per person. Employer access comes from organization membership; removal ends access to the organization's private repositories (and deletes private forks of them) but leaves your account and repositories alone.

### Domain 2: Work with GitHub repositories

**Weight: 14%.** Repository structure and key files, templates and branches, adding and managing files, repository insights and dashboards, and maintenance best practices. Official weight range 10–15%.

📝 Revision notes: [Domain 2: Work with GitHub repositories](notes/domain-2-work-with-github-repositories.md)

- [ ] **Repository management**
  <br>Describe the structure and key files of a GitHub repository (README, LICENSE, CONTRIBUTING, CODEOWNERS, SECURITY); Identify how to create, organize, and maintain repositories using templates and branches; Explain how to add and manage files within a repository; Describe repository insights, stars, feature previews, repository metrics dashboards, and dependency insights for improved visibility; Recognize best practices for repository maintenance and collaboration.
  - 📖 Lesson: [GitHub Repository Management: README, CODEOWNERS, Templates and Insights (GH-900)](https://www.savemycert.com/revision/github-foundations/github-repository-management-readme-codeowners-templates/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)
  - Must know: README is the project's front page; if several exist, GitHub shows .github first, then the root, then docs. A profile README lives in a public repository named after your username.
  - Must know: Without a LICENSE, default copyright applies: others can view and fork a public repository on GitHub but have no right to reuse the code. There is no default license from .github.

### Domain 3: Collaborate using GitHub

**Weight: 14%.** Issues, pull requests and discussions, linking pull requests to issues, templates and assignments, notifications, and Gists, Wikis and GitHub Pages. Official weight range 10–15%.

📝 Revision notes: [Domain 3: Collaborate using GitHub](notes/domain-3-collaborate-using-github.md)

- [ ] **Collaboration tools**
  <br>Describe how to use issues, pull requests, and discussions for collaboration; Explain how to link pull requests to issues and manage templates, filters, and assignments; Identify the purpose of notifications and how to configure them for workflow management; Describe how to use Gists, Wikis, and GitHub Pages to document and share information.
  - 📖 Lesson: [GitHub Collaboration Tools: Issues, Pull Requests, Discussions, Notifications and Pages (GH-900)](https://www.savemycert.com/revision/github-foundations/github-issues-pull-requests-discussions-collaboration/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)
  - Must know: Issues are for actionable work with an owner and an end; discussions are for questions, ideas and announcements; pull requests propose and review a code change.
  - Must know: Q&A discussion categories let a comment be marked as the answer; Announcement categories let only maintain/admin users start threads; people with triage access can convert an issue into a discussion.

### Domain 4: Apply modern development practices

**Weight: 14%.** GitHub Actions, GitHub Copilot and its plans, Codespaces and dev containers, and the github.dev editor. Official weight range 10–15%.

📝 Revision notes: [Domain 4: Apply modern development practices](notes/domain-4-apply-modern-development-practices.md)

- [ ] **Automation and AI tools**
  <br>Describe the purpose and capabilities of GitHub Actions; Identify how GitHub Copilot assists with AI-powered code suggestions, including Copilot agents, Agent Mode, and multi‑model support; Explain the differences between GitHub Copilot for Individuals, Business, and Enterprise; Describe GitHub Codespaces and how to set up, customize, and use dev containers; Explain when to use the github.dev editor and how it differs from Codespaces.
  - 📖 Lesson: [GitHub Actions, Copilot, Codespaces and github.dev: Automation and AI Tools (GH-900)](https://www.savemycert.com/revision/github-foundations/github-actions-copilot-codespaces-github-dev/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)
  - Must know: GitHub Actions runs workflows when events happen — CI/CD, publishing on release, labelling new issues, scheduled jobs — from YAML files that must live in .github/workflows.
  - Must know: Event triggers workflow; a workflow's jobs run in parallel by default, each on its own runner, unless needs: makes one wait; steps run in order within a job; actions are reusable units steps call.

### Domain 5: Manage projects with GitHub

**Weight: 8%.** GitHub Projects layouts and configuration, labels, milestones and workflows, saved replies and assignees, and project insights. Official weight range 5–10%.

📝 Revision notes: [Domain 5: Manage projects with GitHub](notes/domain-5-manage-projects-with-github.md)

- [ ] **Project Tracking and organization**
  <br>Describe GitHub Projects and layout options; Explain how to configure projects, labels, milestones, and workflows; Identify how to use saved replies and assignees to streamline communication; Describe how project insights can be used to track progress and productivity.
  - 📖 Lesson: [GitHub Projects, Labels, Milestones and Insights: Project Tracking (GH-900)](https://www.savemycert.com/revision/github-foundations/github-projects-labels-milestones-insights/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)
  - Must know: A project is owned by a user or organization and can hold issues, pull requests and draft issues from many repositories; built-in fields such as Assignees, Labels and Milestone edit the issue itself.
  - Must know: Table for detail, board for flow, roadmap for time: board columns come from a single select or iteration field, roadmap bars from start and target date or iteration fields.

### Domain 6: Understand privacy, security, and administration

**Weight: 14%.** 2FA and passkeys, repository and organization roles and permissions, Enterprise Managed Users and Copilot policies, visibility and branch protection, and organization settings and teams. Official weight range 10–15%.

📝 Revision notes: [Domain 6: Understand privacy, security, and administration](notes/domain-6-understand-privacy-security-and-administration.md)

- [ ] **Security and access management**
  <br>Describe how to secure accounts with two-factor authentication (2FA) and passkeys; Identify access permissions and roles for repositories and organizations; Explain the purpose of Enterprise Managed Users (EMUs) and organization-wide Copilot policy management; Describe repository privacy options, visibility settings, and branch protection rules; Recognize how to manage organization settings, teams, and roles.
  - 📖 Lesson: [GitHub Security and Access Management: 2FA, Passkeys, Roles and Branch Protection (GH-900)](https://www.savemycert.com/revision/github-foundations/github-security-2fa-roles-permissions-branch-protection/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)
  - Must know: Save your 2FA recovery codes: GitHub Support cannot switch off 2FA, and an account recovery request needs a verified device, SSH key or personal access token.
  - Must know: A passkey replaces both password and 2FA, is phishing-resistant, and is either synced by a cloud service or bound to one device.

### Domain 7: Explore the GitHub community

**Weight: 8%.** Open source and GitHub Sponsors, following users and organizations, the GitHub Marketplace, InnerSource, and forks, templates and discoverable repositories. Official weight range 5–10%.

📝 Revision notes: [Domain 7: Explore the GitHub community](notes/domain-7-explore-the-github-community.md)

- [ ] **Open-source engagement**
  <br>Describe the benefits of open source and GitHub Sponsors; Explain how GitHub supports and advances open-source projects; Identify how to follow users and organizations to stay informed about activity; Describe the GitHub Marketplace and its purpose; Explain how InnerSource applies open-source principles within organizations; Recognize when to use forks, templates, and discoverable repositories to promote collaboration.
  - 📖 Lesson: [Open Source on GitHub: Sponsors, Marketplace, InnerSource, Forks and Discovery (GH-900)](https://www.savemycert.com/revision/github-foundations/github-open-source-sponsors-marketplace-innersource/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)
  - Must know: Open source lets anyone read and reuse code under its license; contributors fork and open pull requests, they do not get write access.
  - Must know: GitHub Sponsors funds developers and organizations through monthly or one-time tiers; personal-account sponsorships carry no fee, organization sponsorships can.

## How to study for GH-900

1. **Read the lesson for each topic** in the checklist above, starting with the heaviest domain. Every lesson is free on the [GH-900 revision notes](https://www.savemycert.com/revision/github-foundations/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide).
2. **Practice straight after reading.** Answer [GH-900 practice questions](https://www.savemycert.com/practice/github-foundations/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide) on the topic you just read. Each option comes with an explanation of why it is right or wrong.
3. **Review what you got wrong**, re-read that lesson section, and tick the topic off only when you get its questions right.
4. **Take a full-length [GH-900 mock exam](https://www.savemycert.com/mocks/github-foundations/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide)** under the real time limit. Aim to pass mocks comfortably before you book.
5. **On the last day**, skim the [GH-900 cheat sheet](https://www.savemycert.com/cheat-sheet/github-foundations/?utm_source=github&utm_medium=readme&utm_campaign=gh-900-study-guide) instead of starting anything new.
